# AGENTS.md

## Назначение и контракт

- `yaleksandr89.github.io` — персональное статическое портфолио, опубликованное на GitHub Pages. Сохранять адрес сайта, русскую `/` и английскую `/en/` версии, существующие страницы 404, ссылки, содержимое резюме, внешний вид и поведение.
- Стек: Astro (static output), TypeScript, HTML, CSS, браузерный JavaScript и `astro-icon`. Сохранять существующие зависимости и `package-lock.json`; ориентироваться на Node.js 24, используемый сборкой. Новые зависимости, платформы, фреймворки и изменения архитектуры требуют решения владельца.
- `src/pages/` содержит маршруты и локализованный контент, `src/layouts/BaseLayout.astro` — общий layout и метаданные, `src/styles/` — стили, `public/` — публичные ресурсы и браузерные скрипты. Сохранять соглашения Astro и строгий `tsconfig.json`, существующее форматирование (2 пробела, LF, английские идентификаторы). Не вводить formatter или linter без отдельного решения.
- Сохранять шесть существующих README и согласованность изменяемых технических инструкций между ними. Не переносить сюда шаблон Composer-пакета, релизный процесс или новые локализации сайта.

## Проверки и безопасность

- В корне репозитория: `npm ci`, `npm run dev` для разработки, `npm run build` для проверки production-сборки, `npm run preview` для просмотра `dist/`. Проверять фактически изменённое поведение обеих версий сайта, включая переходы Astro, если они затронуты. Сборка не заменяет браузерную проверку, когда меняется UI, JavaScript или CSP.
- Перед установкой/сборкой прочитать scripts, lockfile, hooks и конфигурацию; использовать штатного пользователя и изолированное рабочее окружение. Не использовать production credentials, общие данные, широкие удаления, `chmod`/`chown` или автоматическую публикацию. Не добавлять внешнюю выгрузку coverage или public coverage badges.
- Всё в `public/` доступно посетителям, включая обе версии PDF-резюме. Переключатель телефона не является ограничением доступа. Не добавлять секреты и непредусмотренные персональные данные; не изменять существующие документы и публичность данных без решения владельца.
- Сохранять действующие CSP, SEO, локализованные Open Graph-ресурсы и интеграцию аналитики. При изменении сборки, inline scripts или аналитики проверять production CSP и отсутствие утечек; не ослаблять политику безопасности ради прохождения сборки. Не отправлять реальные события аналитики из автоматизированных проверок.
- CI проверяет сборку PR и default branch без прав публикации. `Deploy to GitHub Pages` сохраняет существующий механизм публикации через Astro action и Pages environment; deploy не запускать для PR. Использовать SHA-пины GitHub Actions, минимальные разрешения и не передавать секреты непроверенному коду.

## Работа с Git

- GIT-FIRST для всех tracked files. Сначала читать актуальное состояние, `git remote -v`, применимые правила и затронутые файлы; затем один согласованный batch с точным списком изменений. Сохранять посторонние изменения и индекс владельца. Выполнять полный review, `git diff --check` (включая staged diff), применимые проверки; PASS только для реально выполненных проверок. Не подменять ошибки обещаниями или неподтверждёнными гарантиями.
- Remote READ_ONLY_FOR_AI. Commit, push, создание/merge PR, настройки GitHub и публикация выполняются владельцем; не выполнять reset, restore, clean, stash, rebase, force-push, удаление или изменение истории без отдельного разрешения. Если меняется публичный контракт, появляется риск потери данных или требуется новая зависимость, остановить только зависимую часть и получить решение владельца.
